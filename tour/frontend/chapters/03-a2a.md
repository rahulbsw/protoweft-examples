# A2A: one agent asks another

**Agent2Agent** is for agents that delegate work to other agents. Google started it in 2025, and the Linux Foundation now hosts it. An agent publishes an **agent card** (its name, skills and endpoint) at `/.well-known/agent-card.json`, and other agents send it messages that become **tasks**, with states such as *working*, *input-required* and *completed*.

Our app's agent is a Spring AI `ChatClient` that uses the weather tools. The starter serves it over A2A:

{{snippet agent}}

> Without an API key the tour uses a scripted model, so every run is the same. Set `OPENAI_API_KEY` (any OpenAI-compatible server) to use a real LLM, with no code changes.

:::step a2a.card Read the agent card
This is how agents discover each other: one `GET` returns the card.

{{snippet a2a-card}}
:::

:::step a2a.ask Ask the agent
`SendMessage` carries the question. Behind it, the agent called the `temperature` tool and the answer comes back as the task's `response` artifact, with `TASK_STATE_COMPLETED`. Note the `contextId` in the response.

{{snippet a2a-ask}}
:::

:::step a2a.followup Ask a follow-up in the same conversation
Sending the same `contextId` continues the conversation. "And in Bergen?" only makes sense because the agent remembers we were talking about the weather.

{{snippet a2a-followup}}
:::

> **Takeaway:** `A2aAgentConnector` is an `AgentConnector`. In the last chapter we'll use this agent as if it were just another tool.
